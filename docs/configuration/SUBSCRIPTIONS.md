# Subscription setup and verification

Product: `com.waypoint.maptodo.annual`, auto-renewable one year, intended US price USD 9.99, one-week introductory free trial. App Store Connect must offer the exact desired price point: verify before release; never silently substitute a price. The app always shows `Product.displayPrice` and checks both the configured free offer duration and `isEligibleForIntroOffer`. A trial begins only after Apple purchase confirmation. No install-date trial or production bypass exists.

## App Store Connect (manual release prerequisite)

1. Complete Paid Apps agreement, tax and banking. Create a single subscription group, then the exact product ID above with duration one year; add Chinese/English names and descriptions, review screenshot and notes.
2. Set US base price to USD 9.99 if available, inspect all storefront conversions, and configure a free introductory offer of **one week** for intended territories. One trial per eligible Apple account/subscription group is controlled by Apple.
3. Attach the first subscription to the app version, configure required privacy-policy and terms URLs with genuine published documents, review local in-app policy text against actual service behavior and developer identity, and submit for Apple review only after separate release authorization.
4. This build does not request or support billing grace period: expired transaction dates deny access. If enabling grace period in Connect later, add verified renewal-status and grace-expiration handling before enabling that setting.

Use Xcode Debug > StoreKit > Manage Transactions for expiration/refund scenarios, and reset transactions between scenarios.

## Integration interface

`SubscriptionStore.shared` is MainActor ObservableObject. Gate mutations on `hasAccess`, refreshing at launch and each foreground activation. `refresh()` loads current verified Apple entitlements and products. `hasAccess` defaults false and is recalculated from current entitlements; no persisted access flag. Published `isRefreshing`, `isPurchasing`, `product`, `isEligibleForTrial`, `expirationDate`, `isLocalTestTransaction`, `message` support UI. `SubscriptionView()` owns purchase, restore and system manage sheet. Keep read/export available. Expiration task refreshes at actual transaction expiry; transaction listener refreshes on every update including revoked/unverified results.

## Guarded full unit-test run and StoreKit environment diagnosis

Coordinator's actual `build/unit-guarded.log` run: **31 logic cases passed, all 4 StoreKit lifecycle cases failed**. Session mutations emitted `SKInternalErrorDomain Code=3` while saving configuration/resetting/clearing transactions; product fetch returned nil and off-device `buyProduct` returned `notEntitled`. These are recorded failures, not skips. Runtime was iOS26.5, app was unsigned (`CODE_SIGNING_ALLOWED=NO`; read-only `codesign -d` confirmed no signature).

The identical iOS26.5 CLI configuration-save/off-device purchase issue is discussed in [Apple Developer Forums thread 826971](https://developer.apple.com/forums/thread/826971), including Apple DTS acknowledgement of FB22237318. DTS says a 26.6 fix exists, while the thread reports Xcode26.6 with an older 26.5 simulator still reproduces it. This makes runtime regression a supported hypothesis; unsigned app authorization remains a separate unproven hypothesis. A scheme TestAction reference alone is not established as a fix; `SKTestSession(configurationFileNamed:)` loads the bundled configuration, and the forum reproduction also used an explicit test-plan configuration.

Recommended controlled next check: same simulator, test resources and four cases, enable simulator ad-hoc signing (`CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=-`) under the coordinator's memory guard. If configuration mutations still fail with Code3, compare an older installed runtime or a fixed 26.6 runtime. Never weaken assertions, synthesize purchase state, use real Apple purchases, or report a runtime-failed lifecycle as passing. This diagnosis started no build or simulator.

## Restore bounded waiting

A real-device UI test found AppStore.sync still waiting after30seconds, with Restore disabled and no result message. This was a failure, not successful restoration. Restore now has an independent isRestoring UI state and a15second deadline around both sync and immutable entitlement retrieval. SubscriptionTimeout uses a single-resume locked continuation rather than a task-group race, so an SDK call ignoring cancellation cannot hold the UI waiter indefinitely. The SDK work does not mutate UI state. A restore operation UUID guards result application and cleanup; timed-out late work cannot overwrite a later restore's message or busy state. The existing Done control remains enabled, and timeout releases Restore to allow retry without claiming access. Verified transaction updates continue to reconcile actual entitlements independently. SubscriptionTimeoutTests cover non-cooperative timeout, late result isolation and successful completion; source-only NOT_RUN pending coordinator's guarded build/tests.
