# 行迹 Waypoint — 原生 iOS UI 设计规格

版本：1.0 · 2026-10-11 · 目标平台：iOS 17+ / SwiftUI / MapKit

本文件为设计交付，不代表界面已运行、无障碍已测试、网络服务已接入或购买流程已验证。布局使用 pt；示例内容仅用于设计和明确标注的演示数据。

## 1. 产品意图与设计决策

行迹帮助用户把「今天要做什么」与「要去哪里」放在一起：在地图看见任务位置，添加或完成待办，把多个地点整理成可以调整的出行计划。中文为默认文案，英文品牌 Waypoint 为辅助。地图是主舞台，任务始终可以快速访问。

设计采用温暖奶白、深墨绿和少量珊瑚。奶白承载阅读，墨绿建立清晰主次，珊瑚只强调选中地点、重要提示和行程节点。原生导航、表单、分享面板、购买和权限保持 iOS 熟悉的行为；不依赖自定义字体或图片资产。标识使用原创的简单地点/路径组合与 SF Symbols。

考虑过三种布局：完整列表优先容易浏览但弱化地图；地图占满并以按钮打开列表增加反复切换；采用地图与底部任务卡同屏，在地点和待办之间保持联系。今日页提供更长的列表；规划页承担多地点和多天信息，避免全部挤在主屏。

默认成功标准：用户进入 App 后能看见地图、今天的未完成任务及添加入口；有真实订阅/试用权益时从任一任务进入编辑后保留修改；在定位不可用或没有网络时仍可浏览本地任务和导出；付费状态、天气新鲜度和 AI 可用状态清晰可见。订阅过期保留已有数据的读取与导出。

## 2. 视觉 tokens

### 2.1 颜色

| Token | 浅色值 | 深色值 | 用法 |
|---|---|---|---|
| canvas | `#F5F3EC` | `#101D18` | 全屏背景、列表底 |

| surfaceRaised | `#FFFFFF` | `#21372D` | 选中卡、浮动控件 |
| ink | `#173B32` | `#F2F5EC` | 主文字、图标 |
| secondary | `#56665F` | `#B4C2B7` | 次级文字、metadata |
| accent | `#CF6148` | `#F29B7D` | 地点选中环、装饰、强调图标 |
| softGreen | `#E6EDE4` | `#2D473A` | tag、完成提示、轻选中背景 |
| border | `#D9DFD6` | `#3C5546` | 分隔、未选中描边 |
| actionFill | `#173B32` | `#C5DDC2` | 主要按钮底色 |
| actionLabel | `#FFFFFF` | `#10271D` | 主要按钮文字 |
| warning | 系统橙色 | 系统橙色 | 警告图标，配文字 |
| destructive | 系统红色 | 系统红色 | 删除操作，配文字 |

不使用 opacity 降低正文对比度。浅色已按 WCAG 相对亮度公式计算：ink/surface 12.18:1，secondary/surface 6.01:1，ink/canvas 11.07:1，secondary/canvas 5.46:1，white/actionFill 12.29:1。accent/surface 3.81:1，因此 accent 不用于小号正文或白字小按钮。深色 token 仍需在最终渲染界面进行完整对比度 QA。

### 2.2 字体与数字

使用系统字体，按语义调用 SwiftUI Font，支持 Dynamic Type。中文和英文同时使用系统字体，不强制英文大写。时间、进度数字使用 monospacedDigit，正文不用等宽字体。

| 角色 | 常规尺寸 / 字重 | 典型内容 |
|---|---|---|
| hero | largeTitle / bold，基准 34 | 今日问候、欢迎标题 |
| page | title / bold，基准 28 | 今日、规划、设置 |
| section | title3 / semibold，基准 20 | 今天的行迹、计划详情 |
| cardTitle | headline / semibold，基准 17 | 任务名称、主要卡标题 |
| body | body / regular，基准 17 | 表单、说明、正文 |
| metadata | subheadline / regular，基准 15 | 地点、日期、天气 |
| caption | footnote / regular，基准 13 | 来源、更新时刻、辅助说明 |
| micro | caption / medium，基准 12 | 仅短辅助标记；不承载必要信息 |

任务名称最多在紧凑卡中显示两行；完整详情和编辑不截断。布局先换行，再改为纵向，不用缩小字体容纳长文。中文正文自然行距，段落间距 8pt。

### 2.3 尺寸与形状

间距：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40。屏幕左右基础边距 20，紧凑设备 16；表单遵循系统 inset。卡片内部 20，卡片之间 12，section 之间 24。按钮圆角 16，卡片圆角 24，chip 圆角 14，圆形地图控件 22。

主要按钮最小高度 52，次按钮 48；全部交互触区至少 44×44。小图标 visual size 18–22，完成圈 visual size 24 但 hit area 44。只给浮动地图控件和主屏卡片柔和阴影：墨绿 8% / radius 16 / y 6；常规列表卡用描边或材质，不叠加浓重阴影。分隔线 1pt，使用 border；非必要信息只通过留白区分。

### 2.4 动效与反馈

点击反馈使用原生按钮 pressed state：底色轻变化、可选 scale 0.98。完成任务给予轻成功触感和约 180ms 圈选过渡；不自动滚动地图、不立即移除正在阅读的任务。卡片展开 240–300ms easeInOut。选中地图点后镜头平稳调整，避免反复飞行。Reduce Motion 下关闭缩放、飞行和弹簧，使用短淡入或即时状态切换。加载不采用闪烁持续动画。

## 3. 信息架构与导航

四个系统 TabView：地图（`map`）、今日（`checklist`）、规划（`point.topleft.down.curvedto.point.bottomright.up`，不支持时 `arrow.triangle.turn.up.right.diamond`）、设置（`gearshape`）。标签始终可见，Tab 保留各自导航栈和滚动位置。选中 tint 为墨绿；tab bar 用系统材质叠奶白色，不覆盖内容。

每页有一个 NavigationStack。任务只读详情可用 push 或可关闭 sheet；创建、编辑、搜索和付费墙使用 sheet；规划预览在当前页呈现；导出用系统分享面板。没有独立详情页的首版，任务 sheet 必须支持只读模式，不能因编辑无权益而阻止查看已有任务。地图常驻底部卡是同屏 overlay / safeAreaInset，不是会阻断地图的模态 sheet。地图卡内点击任务查看内容，完成圈只完成任务。

主路径：地图 → 添加任务 → 确认地点和时间 → 保存 → 地图定位新任务；今日 → 完成/编辑；规划 → 选择日期和交通方式 → 生成建议 → 查看时间变化与冲突 → 明确应用；设置 → AI 配置/订阅/导出。创建、编辑、完成与规划应用入口调用统一权益判断，无权益时先展示可关闭付费墙；读取、查看地图、删除已有数据和导出继续可用。

## 4. 地图主屏

### 4.1 默认布局

地图延伸到安全区边缘，状态栏内容保持对比。顶部 safe area 下方为浮动轻材质区域：左侧 20pt 品牌「行迹」与 13pt 动态日期，右侧「添加」圆形 44pt 按钮。下一行搜索 pill 高 48、左右 20，图标 `magnifyingglass`，占位「搜索地点」，右侧可清除输入。当前搜索服务为地点检索，不承诺任务检索。顶部材质只覆盖头部和搜索，不绘制整片实心屏幕。

右侧控件列位于搜索下方，靠右 20，每个 44×44，间距 8：定位、地图显示选项。选项使用 system menu：标准地图 / 卫星地图 / 显示已完成；只出现支持的选项。定位控件可触发授权，不在首次启动弹出权限。

底部任务卡距左右 12，距系统 tab 上缘 8，圆角 24，surface 背景。紧凑状态参考高度 240–320，按内容自动增长；地图剩余可交互区域至少 220pt。顶部可视 grabber 36×4；无障碍用户可用「展开任务列表」按钮，不依赖拖动。

卡内容顺序：

1. 「今天的行迹」20 semibold，右侧「2 / 5 已完成」13；下方 4pt 墨绿进度条。
2. 筛选横排 chips：「待办」「全部」「附近」；默认「待办」，选中 softGreen + ink + checkmark，不只依赖颜色。附近基于可用位置；无位置时点击后说明并提供定位。
3. 最多三个任务行。任务每行 76pt 起，左侧完成圈，中央名称与地点/时间，下方 metadata；右侧可显示轻箭头。
4. 主按钮「添加任务」，旁边次级文字按钮「查看今日」可在卡头右侧出现，不放两个同等级填充按钮。

收起状态只显示标题、数量和单个下一任务；展开后列表占屏高约 60%，保持顶部地图与搜索可用。拖动只从 grabber/卡头启动，列表本身滚动；展开内容较多时不与地图手势抢夺。超大字体和低高度设备改为「查看今日」入口，不让大卡遮满地图。

### 4.2 地图标记和选中状态

地点标记使用 capsule/circle 墨绿底+浅色图标，selected 使用珊瑚外环与 ink label；不把所有任务标题永久展示在地图。选中标记在地图下方卡顶部显示任务摘要，提供「详情」和「导航」。同地点多任务使用数量标记，点击后列出任务。完成项若开启显示使用 checkmark 图形与「已完成」说明，视觉淡化但保留对比。坐标必须来自用户确认地点；异常或缺失坐标的旧数据只出现列表，不能绘制虚构位置。

用户手动拖动地图后不自动回到当前位置。新增任务成功时可选中该任务地点；若键盘/表单刚关闭，等待转场完成。路线只在预览当前计划时绘制，显示交通方式及数据来源。地图标记/路径均来自真实数据或清楚标注的演示模式。

### 4.3 状态文案

| 状态 | UI 与文案 | 可执行动作 |
|---|---|---|
| 无任务 | 小路径图标，「今天，留一点空间给自己」；「把想做的事放到地图上」 | 添加任务 |
| 无有效地点的旧数据 | 卡保留任务；metadata「地点需要确认」 | 有权益时编辑地点 |
| 定位尚未申请 | 定位按钮可用，卡无强制横幅 | 点击定位后系统授权 |
| 定位拒绝 | 轻提示「可搜索地点，也可在设置中允许定位」 | 搜索地点 / 打开系统设置 |
| 定位中 | 控件显示原生 ProgressView | 仍可使用任务列表 |
| 地图暂不可用 | 「地图暂时无法加载，你的任务仍可使用」 | 重试；保留任务 |
| 离线 | 轻胶囊「离线 · 本地任务可用」，不弹反复 alert | 手动重试联网动作 |
| 搜索无结果 | 「没有找到相关地点」 | 修改关键词、取消 |

## 5. 今日页

scrollable 奶白页面。导航大标题「今日」，顶部右侧添加。顶部 24pt 间距后为一句短问候「把今天走成自己的节奏」，下方日期可点选日历。问候不每日更换随机鸡汤。

摘要卡采用两列：左侧「待完成」大数字与「已完成 x 项」，右侧圆形进度环；尺寸由内容决定，圆环不单独承载结果。下方 16pt 天气条：系统天气图标、温度与天气、地点、小号更新时间；加载失败不阻塞待办。

任务按「固定安排」「灵活安排」「已完成」分组，组只在有项时出现。排序遵循用户选择的日期和任务时间；展示时长与当地时间/时区，灵活任务显示可安排窗口。行布局沿用地图卡，但不限制数量。任务标题左对齐、metadata 合理换行，右侧 overflow menu 提供编辑、删除。滑动 actions 可提供完成/删除，但不是唯一入口。完成和编辑遵循实际订阅权益判断；删除已有数据保持可用并确认。

完成动作后该行变为带 checkmark 的已完成状态，短暂保留当前位置；用户可「撤销」。同一组最后一项完成后可显示「今天的任务已完成」轻提示；不强迫进入付费墙。筛选和更改日期不改变任务数据。

每项任务metadata包括所在地日期、时间与时区；不要在未来分组另加可能与其不一致的设备日期。隐藏已完成导致可见列表为空时，显示「当前筛选没有事项」，不能误称当天没有安排。今日context menu删除必须确认，和详情删除使用同等保护。

今日空状态：「这一天还没有安排」/「添加任务，为今天留个方向」。全部完成：「今天的安排完成了」/「好好享受余下的时间」。错误状态的列表保留已读数据，并说明保存/加载是否成功。

## 6. 任务创建、详情和编辑

创建/编辑使用带 NavigationStack 的 sheet，标题「添加任务」/「编辑任务」。左上取消，右上保存；保存使用可见文字，不以图标替代。表单首次焦点在任务标题；无标题保存禁用，在字段下显示「写下这件事的名称」。未保存修改下滑关闭触发系统 confirmationDialog：「继续编辑」「放弃修改」。若编辑期间权益失效，保存前再次判断，保留草稿并提示「订阅已到期，恢复权益后可保存」，不丢失输入。

字段顺序：任务名称（必填）、地点（地图/搜索确认）、日期和当地时间（必填）、预计时长、安排方式（固定/灵活）、提醒、备注（可选，多行）。时长采用易读 picker（如15/30/60分钟）加可编辑数值，展示「预计用时」。灵活安排展开「最早开始」和「最晚完成」窗口，若无法容纳时长显示明确字段错误。地点时区可见并可修正；系统 DatePicker 使用任务时区显示，不能把远方地点的当地时间误当设备时区。

提醒：不提醒 / 开始时 / 提前5、15、30、60分钟；提醒模式普通 / 静音 / 时效通知。界面说明「最终声音与横幅由系统设置决定」，时效模式不保证绕过专注模式。启用提醒后才解释并触发通知权限；拒绝时任务仍能保存，显示「任务已保存，提醒尚未开启」。提醒数量达到系统安排容量时显示实际数量/提示，不宣称所有远期提醒已经安排。

用户点击系统通知时，以通知携带的任务ID读取当前持久化任务并打开详情，不能展示过期通知中的旧内容；订阅过期仍可查看。有任务已被删除时，提供「这项事项已不存在」轻提示，不创建新的占位任务。

地点选择：搜索框、当前位置（仅有权限时）、搜索结果列表，也支持点击地图放置地点。结果呈现地点名称和完整地址，点击后显示小地图确认与「使用这个地点」。不把第一个搜索结果或预设地图中心自动当作已选地点。选取坐标会显示地址正在解析/暂无地址，用户可以明确确认坐标而不会误显示成功解析。

详情页：任务标题、状态、当地时间/时区、时长、安排方式与窗口、地点预览地图、备注、提醒；页底主要动作「标记完成」或「恢复为待办」，次动作「编辑」。地点下显示「在地图中查看」和「前往导航」。导航打开 Apple 地图，不假装 App 提供 turn-by-turn。删除收在 toolbar menu，二次确认「删除这项任务？」并明确不可恢复；若 App 支持撤销则提供 5 秒撤销条。

保存中禁用重复提交，保持输入。保存失败在表单显示「没有保存成功，请重试」，所有草稿保留；只有持久化成功后关闭。完成、更新、删除成功通过简短 inline feedback，不每次弹 alert。

## 7. 规划页与路线

### 7.1 规划首页

导航大标题「规划」。顶部 surface 卡：「把今天的安排，连成顺路的一天」，下方说明「固定安排保持原时间，灵活安排按路程和时间窗口调整」。配置为起止日期、交通方式、是否参考天气、规划方式（本地/AI）。任务范围与所选日期对应，展示「将规划 x 项任务」。卡图不依赖远程封面图片。

页面主按钮「生成规划」，只有有任务及权益可用时才生成；无权益点击进入付费墙。没有任务：「下一段行迹，从这里开始」/「先添加任务，再整理一份顺路的安排」，提供添加入口。所有任务固定时可以检查路线/冲突，但明确「固定安排不会自动改时」。不建立当前数据模型中没有的旅行集合、计划封面、收藏或单独保存行程。

### 7.2 生成与解释

生成 flow：选择范围和交通方式 → 读取固定/灵活任务 → 获取可用路线和天气 → 展示建议与冲突 → 用户明确应用修改。生成中显示「正在整理路线与时间」，取消后保留原任务。生成不自动更改已有事项。

候选列表显示任务名称、地点、当地时间、时长与安排方式。固定安排使用锁图标+「时间固定」，灵活安排显示最早/最晚窗口。跨天按日期 section，跨时区附地区/时区，不能仅依赖设备时间。需要修改某项输入时进入任务编辑，再重算预览；不要用 drag 更改固定任务时间。

交通方式使用 native picker：步行 / 驾车 / 公共交通。切换方式后明确「重新生成后更新建议」，避免自动发起 AI 请求。路线服务不支持当前方式/区域时显示「该方式的路线暂不可用」，可切换或选择明确的估算降级。地点少于两个仍可显示单任务时间建议，不绘制虚假路线。地图路线和列表序号对应，不只用线条颜色区分。

方案展示依据：「路程约 x 分钟」「预留天气缓冲 x 分钟」「固定时间保持不变」。无真实路线数据时明确「采用估算」与估算依据；无天气数据时「天气未参与本次建议」，不能伪造天气风险。冲突包括到达赶不上固定安排、灵活窗口容纳不下、事项重叠；每项冲突给出具体任务和原因。若使用 AI 编排行程，按第 9 节说明发送数据与服务状态。

### 7.3 预览与应用

预览区上半部分可用地图约 35% 可视高度，下半部分按日期的 timeline。节点序号为墨绿圆，选中节点外圈珊瑚；灵活任务同时显示「原时间 → 建议时间」，固定任务明确「保持不变」。天气放在每一天标题附近，勿在每个节点重复展示。底部 CTA「应用建议」，旁边「重新生成」为次动作；有未解决的阻断冲突时禁止直接应用并说明原因。应用前再次核对真实权益与任务版本，避免覆盖用户刚修改的内容。

应用成功：「已更新 x 项灵活安排」，仅修改预览中获用户确认的时间；固定任务不动。取消预览不更改数据。路线计算失败：「暂时无法计算路线」/「你的原安排已保留，可稍后重试」；不显示 0 分钟作为成功结果。部分节点失败明确标注该段。距离和预计耗时只在有服务结果或明确估算标识时显示；更新时间和交通方式可查看。

## 8. 天气和导出

天气组件使用 SF Symbols 与真实天气状态映射。显示城市/地点、温度、摘要、数据时间。请求中的 skeleton 占固定高度；失败显示「天气暂不可用」与重试；没有位置显示「选择地点查看天气」。过期数据显示「上次更新 HH:mm」，保留原值但不暗示为实时。天气来源/署名按实际提供方要求配置，不编造品牌。警示仅在来源提供真实警示数据时显示。

导出入口：今日 toolbar、设置「数据与导出」。先打开导出配置 sheet：起止日期，结束日期包括当天完整范围；格式「纯文本」「Markdown」「日历 ICS」。文案明确包含地点、当地时间/时区、时长和备注；已完成数据根据实际配置选择。纯文本/Markdown 提供「复制」，ICS 提供系统分享。未实现 PDF、CSV、图片导出不显示可点击控件。即使订阅到期，读出/导出仍可用。

预览/生成中显示「正在准备导出」，禁用重复生成。成功打开系统 ShareLink/分享面板。取消系统分享视为取消，不显示成功分享。无内容显示「当前没有可导出的内容」。失败保留配置：「导出未完成，请重试」。文件名以品牌、内容类型、日期构成；日期使用文件安全格式。

## 9. 设置与 AI

设置使用系统 grouped Form，以 brand header 和一张 Pro 状态卡建立温暖感，其他行尽量原生。组顺序：账户与订阅（若没有账户不虚构登录）、AI 助手、地图与提醒、外观与语言、数据与导出、关于与隐私。

地图与提醒显示当前授权状态；点击解释后进入系统设置。外观：跟随系统 / 浅色 / 深色；语言使用系统或实际已实现语言，不宣称未提供翻译。关于显示真实 app version/build。

AI 设置页面顶部说明：「用 AI 帮你整理行程。发送前，你可以查看包含哪些地点和任务。」可用模式来自实际服务：未配置 / 可用 / 测试中 / 不可用。服务商提供 GLM / Qwen / DeepSeek / OpenAI / Gemini 五项，切换服务商保留各自已保存配置，不把某家的密钥当另一家使用。

自带密钥：SecureField「API 密钥」，说明「安全保存在此设备」仅在 Keychain 已接入时使用；末尾四位和「已保存」状态可见，不能展示完整值。独立「测试连接」「保存」按钮；测试成功表示连通，不代表免费或无限调用。支持编辑与移除，移除二次确认。没有接入安全存储前显示真实不可用说明并禁用保存，不能写不成立的安全承诺。

模型 picker 展示官方核验/受支持的模型列表，标注刷新时间并提供「刷新模型」；支持「自定义模型」后才出现模型名字段。刷新失败保留先前列表并说明「暂时无法更新模型列表」。服务地址仅在实际支持自定义地址且用户展开高级设置后呈现。输入验证错误贴近字段，不暴露密钥、请求 header、原始响应或内部堆栈。

使用 AI 前展示确认摘要：日期范围、将发送的地点与任务/时间窗口、是否包含备注；备注默认不包含。提供「生成规划」明确 CTA，用户可取消，并说明费用由所选服务商按其规则计收。生成中允许取消，已有任务保留。结果标为「AI 建议」，先预览可调整，再由用户明确应用；不自动删改任务。AI 生成的天气/路况描述不能作为真实观测展示。

错误文案：未配置「配置 AI 服务后即可生成建议」；无网络「连接网络后重试」；认证失败「密钥未通过验证，请检查后重试」；达到额度/服务限流「服务暂时无法继续处理，请稍后重试」；生成失败「没有生成完整的行程，你的原计划已保留」。只有服务提供准确额度原因时才使用「额度不足」；不要把所有错误都归因为密钥。

## 10. Pro 付费墙与订阅状态

Pro 入口放设置状态卡，以及用户主动触及创建、编辑、完成和应用规划功能时。首次启动可浏览空地图与说明，不能直接以不可关闭付费墙遮挡。已有数据读取、删除与导出保持可用；创建、编辑、完成与规划按真实已验证订阅/试用权益门控。付费墙、限制提示与实现使用同一权益规则。权益说明围绕已实现地图待办、提醒、智能排程；导出保留能力不能宣传成到期后禁止的权益。

付费墙为可关闭 sheet：左上 xmark 44pt 触区，顶部原创路径/地点符号，标题「让每段行迹更从容」，一句「解锁更多规划与整理方式」。权益最多三项，每项图标、17pt标题与15pt一句说明。不要填充夸大承诺或虚假评价。

仅呈现一个年订阅套餐，商品 ID `com.waypoint.maptodo.annual`。产品预期美国价格 USD9.90/年，界面一律展示真实 StoreKit displayPrice，不能把预期数字硬编码为全球售价。资格符合且商品实际配置为1周优惠时显示「7天免费试用」和试用结束后的真实年费；试用由系统购买确认后开始，不从安装日或点击按钮开始。无月套餐、虚假折扣或倒计时。价格未加载显示「正在加载套餐」，购买按钮禁用；加载失败「暂时无法获取套餐」与重试。

主 CTA 无试用为「订阅 Pro」，有资格且明确条件时为「开始7天免费试用」。其下正常可读文本写清价格、周期和自动续订；「恢复购买」「管理订阅」「隐私政策」「使用条款」为可见文字操作。当前原生 App 可使用如实的本地政策阅读页面，不能提供虚构网址；发行时按平台配置要求提供真实政策地址。

购买状态：处理中「正在确认购买」，禁止重复；pending「购买待确认，确认后将自动更新」；成功按 entitlement 更新状态并关闭/显示确认；取消不当成失败；失败「购买未完成，请重试」；恢复无购买「未找到可恢复的购买记录」；恢复成功显示实际权益。已有 Pro 用户看到「Pro 已启用」与管理订阅，不能再次推相同订阅。生产环境不得以本地布尔值、模拟购买或占位价格显示真实订阅已生效。

## 11. 可访问性、适配与隐私交互

- 完成按钮标签「完成任务：{标题}」/「恢复任务：{标题}」，地图点标签包含标题、地点和状态；进度完整读成「今天 5 项任务，已完成 2 项」。
- VoiceOver 读取順序：页面标题 → 核心摘要 → 筛选 → 任务；装饰图标不读；搜索结果可逐项读地点和地址。不要将整页合成一个 accessibility element。
- 卡片展开/收起、排序、筛选都提供可见按钮或 accessibilityAction；不要求精准拖动。
- 最大辅助字号下两列摘要变纵向、chips 可横滚/换行、metadata 换行；任务行自然增高。iPhone 小屏横屏可把主屏任务卡收至单行入口，保留地图操作；不硬写设备高度。
- iPad 使用自适应最大内容宽度 680pt；地图可使用任务侧栏 340–420pt 与地图并列。首次实现可复用四Tab，但禁止把手机卡拉伸满宽。
- 信息状态用文字与形状共同表达；完成=checkmark，冲突=exclamationmark/文字，选中=checkmark+描边；不能只用绿色/珊瑚辨认。
- 使用系统键盘、FocusState、scrollDismissesKeyboard；浮动 CTA 避开键盘和 home indicator。表单错误焦点移到出错字段，并宣布说明。
- 保持系统 back gesture、sheet dismiss 与 keyboard dismissal；所有破坏性操作有清楚名称。请求权限发生在用户主动使用对应功能时。
- 本地/云端、演示/真实、测试/生产状态如存在必须清楚标识；截图演示可以使用样例数据，正式列表不能把样例当用户数据。

## 12. 共用文案与组件契约

| 组件 | 必需输入 | 状态/动作 |
|---|---|---|
| TaskRow | 标题、完成状态、地点、当地时间/时区、时长、灵活窗口 | 选中、完成、编辑；标题不与完成按钮共享点击动作 |
| WeatherStrip | 地点、可选实测值、更新时间、来源 | loading / value / stale / unavailable |
| EmptyState | 图标、标题、说明、可选 CTA | 不显示多个竞争主动作 |
| InlineStatus | 状态类型、简短文字、可选重试 | 永远不覆盖输入或列表 |
| PrimaryButton | 标签、动作、enabled、loading | disabled 可读；loading 标签说明正在进行的动作 |
| MapControl | SF Symbol、label、action | hit44、选中、权限/加载状态 |
| PlanPreview | 日期范围、原/建议时间、交通、route result、冲突 | 尚未生成/生成中/建议/已应用/失败 |
| SubscriptionCard | StoreKit 商品与实际 entitlement | 加载、可购买、处理中、pending、Pro已启用 |

统一按钮：添加任务、保存、取消、完成、编辑、删除、重试、确认地点、导出、生成规划、应用建议、恢复购买。成功状态只在真实操作成功后出现。操作错误采用「发生了什么 + 下一步」的短文，不用「未知错误」或内部错误码充当正文。

## 13. 实现顺序与设计验收

先落实 tokens、四Tab、地图主舞台、TaskRow 和编辑 sheet；再今日/规划；最后天气、AI、导出与 StoreKit 服务状态。所有界面应先完整呈现真实不可用状态，再绑定对应服务，避免交互死端。

提交前的设计 QA 是待执行的验收清单，不是测试结果：

1. 以 iPhone 紧凑宽度、常见宽度和最大辅助字号检查地图可交互区域、表单键盘、任务换行、tab 安全区。
2. 浅/深色检查文字、系统材质、路线标记、disabled state 的对比度；地图变化背景下顶部内容仍可读。
3. VoiceOver 完成任务、添加地点、调整路线、关闭付费墙和恢复购买；Reduce Motion 下无大幅镜头/缩放。
4. 无定位、拒绝通知、离线、搜索空、路线失败、天气过期、AI 未配置、商品未加载等状态都有准确文案和可继续的任务操作。
5. 保存失败保留草稿，导出取消不报成功，购买取消不报失败，Pro状态来自真实权益。
6. 演示数据与生产数据清晰区分；无图片资源缺失、假价格、假天气、假路线或未实现的可点击入口。

本规格的视觉 tokens、尺寸与文案可直接交给实现。真实 API 字段、数据模型和订阅权益应与架构/服务接口保持一致；接口发现差异时更新本文件与 UI，不能以占位成功掩盖差异。
